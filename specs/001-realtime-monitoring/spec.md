# 功能規格書：即時資料分析與監控系統

**Feature Branch**: `001-realtime-monitoring`

**建立日期**: 2026-10-22

**狀態**: Draft

**輸入**: 使用者描述：「為整個即時資料分析與監控系統建立功能規格（涵蓋使用者管理、資料管理、即時監控、資料分析、系統管理五大模組）。」

## Clarifications

### Session 2026-10-22

- Q: 當多位使用者同時更新同一筆資料記錄時，系統應如何處理寫入衝突？ → A: 最後寫入者勝出（Last-Write-Wins），直接以最新一次更新覆蓋，不偵測衝突。
- Q: 通行憑證的有效期限應設定為多久？ → A: 預設 60 分鐘，並可透過環境設定調整。
- Q: 批量導入單一檔案的筆數與檔案大小上限應設為多少？ → A: 最多 10,000 筆 / 10 MB。
- Q: 系統日誌與即時資料的歷史記錄應保留多久？ → A: 即時資料保留 30 天、系統日誌保留 90 天，並可透過環境設定調整。
- Q: 當 Admin 嘗試降級或停用系統中唯一的 Admin 帳號時，系統應如何處理？ → A: 禁止操作，系統拒絕降級／停用最後一位啟用中的 Admin 並回報原因。

## 使用者情境與測試 *(必要)*

本系統服務三種角色：**管理員（Admin）**、**一般使用者（User）**、**檢視者（Viewer）**。使用者故事依價值重要性排序，每個故事皆可獨立驗證並單獨交付價值。

### 使用者故事 1 — 安全登入與角色授權 (Priority: P1)

使用者以帳號密碼登入系統，系統核發具時效的通行憑證，並依其角色（Admin／User／Viewer）決定可執行的操作。未登入者無法存取任何受保護的功能。

**為何此優先級**：這是整個系統的安全地基。沒有可靠的登入與角色授權，其餘所有模組的資料與操作都無從保護，因此列為最高優先。

**獨立測試**：可單獨建立帳號、登入取得憑證、以不同角色嘗試存取受保護資源，驗證授權與拒絕行為，即構成一個可展示的最小可行產品（MVP）。

**驗收情境**：

1. **Given** 一個已註冊且啟用的帳號，**When** 使用者輸入正確帳號密碼登入，**Then** 系統核發有效通行憑證並回傳該使用者的身分與角色。
2. **Given** 使用者輸入錯誤密碼，**When** 嘗試登入，**Then** 系統拒絕登入並回傳明確但不洩漏細節的錯誤訊息（不透露是帳號還是密碼錯誤）。
3. **Given** 一個 Viewer 角色的使用者，**When** 嘗試建立資料，**Then** 系統拒絕並回傳權限不足的訊息。
4. **Given** 通行憑證已過期，**When** 使用者以該憑證存取受保護資源，**Then** 系統拒絕並引導使用者重新登入。

---

### 使用者故事 2 — 資料記錄的建立與管理 (Priority: P1)

一般使用者與管理員可建立、瀏覽、更新、刪除資料記錄（含標題、數值、分類、時間戳）。瀏覽支援分頁、篩選與排序。更新與刪除僅限該筆記錄的建立者或管理員。所有角色皆可瀏覽資料。

**為何此優先級**：資料記錄是系統的核心業務資產，分析與監控皆建立於其上。與登入授權同為系統能運作的必要基礎，故列為 P1。

**獨立測試**：登入後建立數筆資料，驗證分頁／篩選／排序，並以非擁有者身分嘗試更新他人資料以驗證權限邊界，即可獨立展示價值。

**驗收情境**：

1. **Given** 一個 User 已登入，**When** 建立一筆含標題、數值、分類的資料，**Then** 系統儲存該筆記錄並標記其為建立者。
2. **Given** 資料庫中有多筆記錄，**When** 使用者以分類篩選並依時間排序請求第 2 頁，**Then** 系統回傳符合條件、正確排序且分頁的結果與總筆數。
3. **Given** 一筆由 A 使用者建立的記錄，**When** B 使用者（非 Admin）嘗試更新或刪除它，**Then** 系統拒絕操作。
4. **Given** 一筆由 A 使用者建立的記錄，**When** A 本人或 Admin 更新它，**Then** 系統儲存變更並更新最後修改時間。
5. **Given** 一個 Viewer 已登入，**When** 嘗試建立、更新或刪除資料，**Then** 系統一律拒絕但仍允許其瀏覽。

---

### 使用者故事 3 — 即時資料監控與異常告警 (Priority: P1)

系統每秒自動產生模擬資料並即時推送至已連線的前端，前端以折線圖／柱狀圖即時更新。當數值超過設定閾值時標記為異常並以明顯視覺提示呈現。

**為何此優先級**：「即時監控」是本系統的核心價值與題目主軸，直接體現系統存在的目的，故列為 P1。

**獨立測試**：開啟即時監控頁面，觀察圖表每秒更新；人為注入超過閾值的數值，驗證異常被標記並以視覺提示呈現。

**驗收情境**：

1. **Given** 使用者開啟即時監控頁面，**When** 系統每秒產生新資料，**Then** 前端圖表在 1 秒內更新呈現最新資料點。
2. **Given** 產生的資料數值超過異常閾值，**When** 該資料被推送，**Then** 前端以明顯一致的視覺提示（如顏色或標記）呈現該異常點。
3. **Given** 多位使用者同時開啟即時監控頁面，**When** 系統產生新資料，**Then** 所有連線者皆同步收到同一份即時資料。
4. **Given** 前端連線中斷後重新連上，**When** 重新建立連線，**Then** 系統恢復推送後續即時資料而不需重新登入流程以外的手動操作。

---

### 使用者故事 4 — 資料統計分析與匯出 (Priority: P2)

使用者可對資料進行統計分析（總計、平均、最大、最小）、依時間範圍查詢、依分類聚合，並檢視趨勢圖表。分析結果可下載為 Excel 檔。

**為何此優先級**：分析能力讓資料產生決策價值，是重要功能，但需建立在資料管理（US2）之上，故列為 P2。

**獨立測試**：在既有資料上請求統計與分類聚合，驗證數字正確；指定時間範圍查詢趨勢；下載 Excel 並確認內容與畫面一致。

**驗收情境**：

1. **Given** 資料庫中有多筆記錄，**When** 使用者請求統計分析，**Then** 系統回傳正確的總計、平均、最大與最小值。
2. **Given** 使用者指定一個時間範圍，**When** 請求趨勢資料，**Then** 系統僅回傳該範圍內的資料並呈現為趨勢圖。
3. **Given** 資料含多個分類，**When** 使用者請求分類聚合，**Then** 系統回傳每個分類的彙總結果。
4. **Given** 畫面上有分析結果，**When** 使用者點擊匯出，**Then** 系統產生與畫面一致的 Excel 檔供下載。

---

### 使用者故事 5 — 批量資料導入 (Priority: P2)

一般使用者與管理員可透過上傳 CSV 或 JSON 一次導入多筆資料記錄，系統驗證格式並回報成功與失敗的筆數。

**為何此優先級**：批量導入大幅提升建檔效率，是重要但非系統可運作的必要條件，故列為 P2。

**獨立測試**：上傳一份含正確與錯誤資料列的範例檔，驗證正確列被導入、錯誤列被拒絕並回報明確原因。

**驗收情境**：

1. **Given** 一個 User 已登入，**When** 上傳一份格式正確的 CSV，**Then** 系統導入所有記錄並回報成功筆數。
2. **Given** 上傳檔案中部分列格式錯誤，**When** 執行導入，**Then** 系統導入正確列、略過錯誤列並回報每列的失敗原因。
3. **Given** 一個 Viewer 已登入，**When** 嘗試批量導入，**Then** 系統拒絕操作。

---

### 使用者故事 6 — 系統管理與稽核 (Priority: P3)

管理員可查看所有使用者列表、調整使用者角色、查詢系統日誌、檢視資料庫狀態，以及查詢即時資料的歷史記錄。這些功能僅限管理員。

**為何此優先級**：管理與稽核能力對長期維運重要，但不影響一般使用者的核心流程，故列為 P3。

**獨立測試**：以 Admin 登入檢視使用者列表、變更某使用者角色、查詢日誌與資料庫狀態；再以非 Admin 身分嘗試存取同一功能以驗證被拒絕。

**驗收情境**：

1. **Given** 一個 Admin 已登入，**When** 請求使用者列表，**Then** 系統回傳所有使用者及其角色與啟用狀態。
2. **Given** 一個 Admin 已登入，**When** 變更某使用者的角色，**Then** 系統更新該使用者角色，且該使用者後續操作權限隨之改變。
3. **Given** 一個非 Admin 使用者，**When** 嘗試存取任一系統管理功能，**Then** 系統一律拒絕。
4. **Given** 系統已運行一段時間，**When** Admin 查詢系統日誌或即時資料歷史，**Then** 系統回傳可依時間與條件篩選的記錄。

---

### 邊界情況

- 當使用者以已過期或無效的憑證存取時，系統如何回應？（應拒絕並引導重新登入，不洩漏內部細節）
- 當同一帳號／電子郵件重複註冊時，系統如何處理？（應拒絕並回報已存在）
- 當批量導入檔案為空、格式完全錯誤或超過大小上限時，系統如何回應？
- 當分析查詢的時間範圍沒有任何資料時，系統如何呈現？（應呈現清楚的空狀態而非錯誤）
- 當即時資料前端連線中斷或網路不穩時，系統如何處理重連與資料連續性？
- 當資料庫短暫無法連線時，系統如何避免崩潰並維持服務？
- 當 Admin 調整自己的角色或停用 Admin 帳號時，系統禁止降級或停用最後一位啟用中的 Admin，以防止將管理權限鎖死。
- 當多位使用者同時更新同一筆記錄時，系統以「最後寫入者勝出」處理，不偵測衝突。

## 需求 *(必要)*

### 功能需求

**使用者管理與授權**

- **FR-001**: 系統必須允許使用者以帳號、電子郵件與密碼註冊，並拒絕重複的帳號或電子郵件。
- **FR-002**: 系統必須在登入成功時核發具時效的通行憑證（預設有效期 60 分鐘，可透過環境設定調整），並在憑證過期後拒絕以其存取受保護資源。
- **FR-003**: 系統必須以安全方式保存密碼（不得以明文儲存），並在驗證失敗時回傳不洩漏內部細節的錯誤訊息。
- **FR-004**: 系統必須支援三種角色（Admin／User／Viewer），並依下方權限矩陣對每項操作強制授權。
- **FR-005**: 系統必須提供查詢「目前登入使用者」身分與角色的能力。

**資料管理**

- **FR-006**: 系統必須允許具權限的使用者建立資料記錄，記錄至少包含標題、數值、分類與時間戳，並記錄其建立者。
- **FR-007**: 系統必須支援資料記錄的瀏覽，並提供分頁、依分類等條件篩選，以及依時間等欄位排序。資料記錄採「團隊共享」可見性設計：**所有登入者（Admin／User／Viewer）皆可讀取任一筆資料記錄（列表與單筆讀取皆不限建立者）**；寫入（建立／更新／刪除）則依 FR-006／FR-008 限制。
- **FR-008**: 系統必須僅允許該筆記錄的建立者或 Admin 更新或刪除該記錄，並拒絕其他使用者的更新／刪除。
- **FR-009**: 系統必須記錄每筆記錄的建立時間與最後更新時間。
- **FR-010**: 系統必須允許具權限的使用者透過 CSV 或 JSON 批量導入資料（單一檔案上限 10,000 筆 / 10 MB），並回報成功與失敗的筆數及每筆失敗原因。

**即時監控**

- **FR-011**: 系統必須以固定頻率（每秒）自動產生模擬資料。
- **FR-012**: 系統必須將每秒產生的即時資料即時推送給所有已連線的前端，並支援多個同時連線者同步接收。
- **FR-013**: 系統必須在數值超過可設定的異常閾值時標記該資料為異常。
- **FR-014**: 前端必須以即時更新的折線圖與柱狀圖呈現即時資料，並以一致且明顯的視覺提示標記異常點。
- **FR-015**: 系統必須將即時資料以定期或條件觸發的批次方式持久化保存（而非每筆單獨寫入），批次策略必須可設定。

**資料分析**

- **FR-016**: 系統必須能計算資料的統計指標，至少包含總計、平均、最大與最小值。
- **FR-017**: 系統必須支援依時間範圍查詢資料並呈現趨勢。
- **FR-018**: 系統必須支援依分類對資料進行聚合彙總。
- **FR-019**: 系統必須允許使用者將分析結果下載為 Excel 檔，且內容與畫面呈現一致。

**系統管理（僅 Admin）**

- **FR-020**: 系統必須允許 Admin 查看所有使用者列表（含角色與啟用狀態）。
- **FR-021**: 系統必須允許 Admin 調整使用者角色，並使變更即時生效於後續授權；但必須禁止降級或停用最後一位啟用中的 Admin，並回報原因。
- **FR-022**: 系統必須允許 Admin 查詢系統日誌，並支援依時間與條件篩選。
- **FR-023**: 系統必須允許 Admin 檢視資料庫狀態。
- **FR-024**: 系統必須允許 Admin 查詢即時資料的歷史記錄。

**通用品質**

- **FR-025**: 系統必須對錯誤進行明確處理並記錄系統活動日誌，且不得向終端使用者揭露內部堆疊或錯誤碼。
- **FR-026**: 系統必須提供健康檢查能力以供監看服務是否正常運作。
- **FR-027**: 前端各頁面必須維持一致的用語、版面與互動模式，並一致管理登入狀態與登入／登出行為。
- **FR-028**: 系統必須在資料庫短暫無法連線時以優雅方式降級（重試退避）而非直接崩潰。
- **FR-029**: 系統必須依可設定的保留政策保存歷史資料（預設即時資料 30 天、系統日誌 90 天），並支援逾期清理。

### 權限矩陣（RBAC）

| 操作 | Admin | User | Viewer |
|------|:-----:|:----:|:------:|
| 瀏覽資料 | ✅ | ✅ | ✅ |
| 建立資料 | ✅ | ✅ | ❌ |
| 更新／刪除自己的資料 | ✅ | ✅ | ❌ |
| 更新／刪除他人資料 | ✅ | ❌ | ❌ |
| 批量導入 | ✅ | ✅ | ❌ |
| 查看使用者列表／權限管理 | ✅ | ❌ | ❌ |
| 系統日誌／資料庫狀態 | ✅ | ❌ | ❌ |
| 即時監控／分析圖表 | ✅ | ✅ | ✅ |

### 關鍵實體 *(涉及資料時納入)*

- **使用者（User）**：代表系統的操作者，具唯一帳號與電子郵件、加密保存的密碼、角色（Admin／User／Viewer）、啟用狀態與建立時間。
- **資料記錄（DataRecord）**：使用者建立的業務資料，含標題、數值、分類、時間戳、建立者（關聯至使用者）、建立與最後更新時間。
- **即時資料（RealtimeData）**：由生成器產生的即時資料點，含數值、分類、是否異常、產生時間。
- **系統日誌（SystemLog）**：系統活動與錯誤的記錄，含等級、訊息、相關使用者（可為空）、相關端點與時間。

## 成功標準 *(必要)*

### 可衡量成果

- **SC-001**: 新使用者可在 2 分鐘內完成註冊並成功登入。
- **SC-002**: 即時資料從產生到前端呈現的端到端延遲在 95% 的情況下不超過 1 秒。
- **SC-003**: 一般資料查詢在 95% 的情況下於 300 毫秒內回應（不含冷啟動）。
- **SC-004**: 系統可支援至少 50 位使用者同時連線即時監控而不中斷推送或明顯延遲。
- **SC-005**: 權限控制正確率 100%：任何未授權的建立／更新／刪除／管理操作皆被拒絕，無任何越權成功案例。
- **SC-006**: 批量導入一份 1,000 筆的範例檔可在 10 秒內完成並正確回報成功與失敗筆數。
- **SC-007**: 異常資料點 100% 被正確標記並在前端以一致視覺提示呈現。
- **SC-008**: 分析結果匯出的 Excel 內容與畫面呈現 100% 一致。
- **SC-009**: 資料庫短暫中斷（如 10 秒內）期間服務不崩潰，恢復後可繼續正常運作。

## 假設

- 使用者具備穩定的網路連線以維持即時資料推送。
- 系統預設時區為 Asia/Taipei，時間戳以 ISO 8601 格式呈現。
- 即時資料為模擬產生，用於展示監控能力，不代表真實外部來源。
- 預設提供三組種子測試帳號（Admin／User／Viewer 各一），於系統初始化時建立。
- 行動裝置的原生體驗不在本版範圍內，以桌面瀏覽器操作為主。
